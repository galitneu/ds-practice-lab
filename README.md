# מעבדת התרגול של גלית · Data Science Practice Lab

סביבת עבודה לד״ר גלית נויפלד קרושינסקי, מנהלת מחקרי בריאות המשלימה לימודי מדע הנתונים. המטרה: לעבור מידע בסיסי בפייתון לעבודה עצמאית ב־EDA, בניית מודלים והסקת מסקנות זהירה. הנתונים הם חומר לימודי היסטורי, ולא בסיס להחלטות רפואיות.

## מתחילות

בטרמינל, משורש המאגר (Python 3.11–3.13, מומלץ 3.12):

</div>

```bash
git clone https://github.com/galitneu/ds-practice-lab.git
cd ds-practice-lab
./setup.sh
source .venv/bin/activate
jupyter lab
```

<div dir="rtl">

להתקנת גרסאות Python המדויקות שאומתו במעבדה: לאחר יצירת הסביבה הריצי `.venv/bin/python -m pip install -r requirements-lock.txt` (נבדק ב־Python 3.12 על Linux).

ההתקנה דורשת רשת; התרגול לאחריה עובד עם קובצי הנתונים המקומיים. ב־Codex הריצי `./setup.sh` פעם אחת בכל סביבה חדשה. ההתקנה יוצרת `.venv` ואינה משנה את Python המערכתי. אם LightGBM מדווח על חוסר ב־OpenMP, התקיני את ספריית OpenMP של מערכת ההפעלה (למשל `libgomp1` בלינוקס).

## עבודה עם Codex בתוך ChatGPT

פתחי סביבת Codex עם המאגר `galitneu/ds-practice-lab`, ובקשי לקרוא את `AGENTS.md`. בסביבה שתומכת בעריכת מאגר והרצת פקודות, Codex יוכל לבדוק קוד ולהריץ בדיקות. בשיחת ChatGPT ללא גישה למאגר, צרפי את הקוד ואת פלט הבדיקה לקבלת משוב. ההנחיות במאגר מגדירות מורה סבלנית: שאלה, רמז, קטע קוד חלקי; פתרון מלא רק לפי בקשה מפורשת.

## שגרת תרגול יומית

1. בחרי מחברת אחת ב־`exercises/`, קראי את המטרה וכתבי השערה.
2. הריצי את תא ההכנה. השלימי את הפונקציה ב־`src/exNN.py`; המחברת מציינת את החתימה המדויקת.
3. בטלי את ההערות סביב הקריאה לפונקציה במחברת. הוסיפי גרפים ודיון; שמרי את המחברת עם התוצרים שלך.
4. הריצי `make check EX=03` (עם שתי ספרות). תקני כישלון אחד בכל פעם.
5. בקשי review על הקוד ועל ההחלטות המחקריות. סיימי עם מסקנה ומגבלה.
6. בקשי לעדכן את `PROGRESS.md` ובחרי את הצעד הבא.

כל מחברת עצמאית: אין חובה להשלים את הקוד של התרגילים הקודמים כדי להתחיל אותה. לצורך תרגול הקשר בין שלבים, אפשר לייבא את הקוד שכבר כתבת. הפונקציות נמצאות בקבצים כדי שיהיה קל לבדוק אותן; ה־EDA והסיפור המחקרי נשארים במחברת.

## בדיקות וקבצים

`make test` מריץ את כל בדיקות הלומדת. **במאגר ההתחלתי 12 בדיקות ייכשלו בכוונה**, עם `NotImplementedError`. זהו סימון שהפונקציות ממתינות לך, ולא תקלה בהתקנה. `make check EX=03` מריץ רק את תרגיל 3.

`make notebooks` מאמת ומריץ את כל המחברות במצב ההתחלתי: הקריאות לקוד שטרם נכתב נמצאות בהערות, לכן הן בטוחות להרצה. לאחר השלמה תוכלי לבטל את ההערות. הבדיקות אינן בודקות אוטומטית את איכות הגרפים והמסקנות; המחוון במחברת וה־review משלימים זאת.

למתחזקת בלבד, או לבקשה מפורשת לבדוק פתרונות: `USE_SOLUTIONS=1 make test` בודק את פתרונות הייחוס בלי להעתיק אותם לתיקיית העבודה. `make verify` בודק פתרונות, כישלון מכוון של כל starters והרצת מחברות. הפקודה האחרונה מיועדת לענף ההתחלתי; אחרי שאת פותרת תרגילים אין ציפייה שכולם ייכשלו.

- `src/` — הפונקציות שאת משלימה; `src/common.py` טוען נתונים מקומיים.
- `tests/` — חוזי קוד ותרחישי קצה; מותר לקרוא אותם.
- `solutions/` — פתרונות ייחוס לפונקציות, לא לפתוח בזמן תרגול בלי בקשה מפורשת.
- `data/README.md` — מקורות, רישיונות, הגדרת יעדים ומגבלות.
- `PROGRESS.md` — יומן למידה, מתעדכן רק כשתבקשי.

הצלחה על חלוקת מבחן אחת אינה הוכחה להכללה. אל תכווני שוב ושוב לפי test; הפרידי train/validation/test בפרויקט שלך. אין להשתמש בשמות, מזהים או משתנים שנוצרו לאחר התוצאה כקלט לחיזוי.
